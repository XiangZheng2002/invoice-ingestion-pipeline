## Project Overview

Email Invoice Recognition System - A Flask web application that automatically fetches emails from QQ Mail via IMAP, detects invoice emails, extracts invoice information using Baidu OCR API, and exports the data to CSV for expense reporting.

## Development Commands

### Setup
```bash
# Create virtual environment
python3 -m venv venv

# Activate virtual environment
source venv/bin/activate  # macOS/Linux
venv\Scripts\activate     # Windows

# Install dependencies
pip install -r requirements.txt
```

### Running the Application
```bash
# Start development server (debug mode enabled)
python run.py

# Access at http://127.0.0.1:5000
```

### Environment Configuration
- Copy `.env.example` to `.env` (if exists) or create `.env` with required variables
- Required environment variables:
  - `SECRET_KEY`: Flask secret key
  - `ENCRYPTION_KEY`: Auto-generated by CryptoUtil on first run, must be saved to `.env`
  - **Baidu OCR credentials are now configured via web interface** (see below)

### Baidu OCR Configuration
- **New**: OCR credentials are configured through the web UI at `/config`
- Users enter their own Baidu OCR credentials (APP_ID, API_KEY, SECRET_KEY)
- Credentials are encrypted and stored in the `config` table
- `OCRService` reads from database first, falls back to `.env` if not found
- This allows multi-user deployment where each user uses their own OCR quota

## Architecture

### Application Structure
- **Entry Point**: `run.py` - Creates and runs the Flask app
- **App Factory**: `app/__init__.py` - `create_app()` initializes Flask, CSRF protection, database, and registers blueprints
- **Configuration**: `app/config.py` - Config class with environment-based settings
- **Database**: SQLite with direct connection management (no ORM)

### Layer Organization

**Models Layer** (`app/models.py`):
- Direct SQLite3 connections via `get_db_connection(db_path)`
- Model classes: `Email`, `Invoice`, `Config`
- Each model has static methods: `create()`, `get_all()`, `get_by_id()`, `count()`
- Database initialization: `init_db(db_path)` creates 4 tables: emails, invoices, config, export_history

**Routes Layer** (`app/routes/`):
- Three blueprints: `main.bp`, `email_routes.bp`, `invoice.bp`
- Registered in `app/__init__.py`
- Routes handle HTTP requests and delegate to services

**Services Layer** (`app/services/`):
- `EmailService`: IMAP connection to QQ Mail, email fetching/parsing, attachment handling
  - Connects to `imap.qq.com:993` with SSL
  - Key methods: `connect()`, `fetch_emails()`, `parse_email()`, `download_attachment()`
  - Handles date filtering with client-side fallback for QQ Mail IMAP bugs
- `InvoiceDetector`: Rule-based invoice email detection
  - Multiple detection strategies: keywords in subject/body, known sender domains, attachment analysis
  - Methods: `is_invoice_email()`, `detect_invoice_type()`, `extract_invoice_files()`, `get_detection_confidence()`
- `OCRService`: Baidu OCR integration for invoice recognition
  - Uses `AipOcr` client with VAT invoice API (`vatInvoice()`)
  - Parses structured invoice data from OCR results
  - Falls back gracefully if OCR not configured
- `csv_exporter.py`: CSV export functionality
- `file_handler.py`: File processing utilities

**Utils Layer** (`app/utils/`):
- `crypto.py`: `CryptoUtil` class using Fernet (symmetric encryption) for QQ Mail password storage
  - Auto-generates encryption key on first run if not in `.env`
- `validators.py`: Input validation and sanitization

### Data Flow

1. **Email Fetching**:
   - User configures QQ Mail credentials via `/config` route
   - Credentials encrypted by `CryptoUtil` and stored in `config` table
   - `EmailService.connect()` → `fetch_emails(since_date, before_date)` → `parse_email()`
   - Email data saved to `emails` table via `Email.create()`

2. **Invoice Detection**:
   - `InvoiceDetector.is_invoice_email()` analyzes subject, sender, body, attachments
   - Detected invoices marked with `is_invoice=True` in database
   - Invoice types: PDF attachment, image attachment, email body, electronic invoice link

3. **OCR Processing**:
   - Invoice files extracted via `InvoiceDetector.extract_invoice_files()`
   - `OCRService.recognize_invoice()` sends to Baidu API
   - Structured data parsed via `parse_vat_invoice()`
   - Invoice records created in `invoices` table with foreign key to `emails.email_id`

4. **Export**:
   - Query invoices from database
   - Generate CSV with expense report fields
   - Track exports in `export_history` table

### Security Considerations

- **CSRF Protection**: Enabled via `flask_wtf.csrf.CSRFProtect()`
- **Password Encryption**: QQ Mail passwords encrypted with Fernet before database storage
- **Encryption Key Management**: Must persist `ENCRYPTION_KEY` in `.env` - losing it makes encrypted data unrecoverable
- **File Upload**: 50MB limit, allowed extensions in `Config.ALLOWED_EXTENSIONS`
- **Input Sanitization**: `Validators.sanitize_filename()` cleans attachment filenames

### Database Schema

**emails table**:
- Stores email metadata and processing status
- `email_id` (UNIQUE): IMAP message ID
- `is_invoice`, `processed`: Boolean flags for workflow

**invoices table**:
- Stores OCR-extracted invoice data
- Foreign key: `email_id` references `emails.email_id`
- Fields: invoice codes/numbers, buyer/seller info, amounts, tax
- `ocr_confidence`: Float tracking recognition quality

**config table**:
- Key-value store with encryption support
- `encrypted` boolean flag determines if `CryptoUtil` decryption needed
- Used for QQ Mail credentials and app settings

### Frontend Architecture

- **Templates**: Jinja2 templates in `app/templates/`
  - `base.html`: Base layout with Bootstrap 5
  - Page templates: `index.html`, `config.html`, `email_list.html`, `invoice_list.html`
- **Static Assets**: `app/static/js/` contains jQuery-based interactivity
  - `main.js`: Common functionality
  - `invoice.js`: Invoice-specific features
- **UI Libraries**: Bootstrap 5, DataTables, SweetAlert2

### QQ Mail Integration Notes

- Uses authorization code (not password) from QQ Mail IMAP settings
- IMAP date filtering has bugs - `EmailService.fetch_emails()` includes client-side date filter as fallback
- Connection must be in SELECTED state for FETCH operations
- Email encoding detection tries multiple charsets: utf-8, gb2312, gbk, gb18030

### OCR Integration Notes

- Baidu OCR free tier: 500 calls/day
- Primary API: `vatInvoice()` for VAT invoices
- Fallback: `receipt()` for general invoices
- Returns structured data with field-level extraction
- Application handles missing OCR config gracefully (disabled state)

## Key Design Patterns

- **Application Factory Pattern**: `create_app()` for Flask initialization
- **Service Layer Pattern**: Business logic separated from routes
- **Static Method Pattern**: Models use static methods instead of instance methods (no ORM)
- **Strategy Pattern**: `InvoiceDetector` uses multiple detection strategies with confidence scoring
